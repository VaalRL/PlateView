# 0005. 小聯盟支援：依層級按需載入，球員數據以 `leagueListId=mlb_milb` 一次取得各層級

- Status: Accepted
- Date: 2026-09-24

## Context

PlateView 目前只看大聯盟（`sportId=1`）。需求是支援小聯盟，並且**球員在大小聯盟間升降時要顯示正確**。

實測（2026-09-24）：

- 小聯盟各層級（AAA=11、AA=12、A+=13、A=14）的賽程、逐局比分、boxscore、戰績、球隊資料都拿得到，CORS 開放，回應大小與延遲跟大聯盟相同（單層級每日比分約 12.8 KB gzip）。
- 首頁若一次載入四個層級，首屏流量變 5 倍、直播輪詢每小時約 7.5 MB；只載入使用者選的層級則與現況相同（每小時約 1.5 MB）。
- 小聯盟各層級每層 30 隊，`/teams` 回應**沒有隊色**。

### 球員升降：現況的三個錯誤

1. **升上大聯盟後，小聯盟數據就消失**。`getPlayerDetail` 只在「完全沒有大聯盟數據」時才補抓小聯盟。實例：Brian Serven（運動家）2026 年 AAA 61 場、MLB 28 場，球員頁只看得到 MLB 28 場。
2. **被下放後，大聯盟數據被標成小聯盟**。數據區標題旁的層級標籤讀的是「目前所屬球隊」的層級，不是數據本身的層級。球員人在 AAA 時，頁面顯示的是 MLB 數據卻標著 `Triple-A`。
3. **我的最愛戰報看不到下放球員的比賽**：戰報只查大聯盟 gameLog。

### 查證過的 API 行為

- `sportIds=1,11,12,13,14`（多值）**會被忽略**，只回大聯盟。
- `leagueListId=mlb_milb` 一次回傳所有層級，每筆 split 帶 `sport.id`：
  - `season`：每個層級一筆；同層級跨隊時另有一筆合計（無 `team`、`numTeams=2`）排在前面。
  - `career`：每個層級一筆，另有 `sport.id=21`（`Minors`）的小聯盟合計。
  - `gameLog`：各層級的比賽混在一起，**依層級分段而非依日期排序**。
  - `sabermetrics`（WAR 等）只有大聯盟。
- 大小：Serven 的球員頁請求由 4.4 KB 變 9.6 KB（gzip）；純大聯盟球員（Judge）由 6.7 KB 變 7.5 KB。原本純小聯盟球員要發兩次請求，現在只要一次。
- `/people/search` 本來就找得到小聯盟球員，不需修改。

## Decision

### A. 球員層級（升降正確性）

1. `getPlayerDetail` 與我的最愛戰報的 gameLog 請求一律加 `leagueListId=mlb_milb`，移除原本的兩段式補抓。
2. 新增 `src/utils/playerLevels.ts` 純函式：列出球員有數據的層級（排除 `sport.id=21` 合計）、取某層級的數據（跨隊時取合計那筆）、決定預設層級、依日期排序 gameLog。
3. 球員頁數據區加上**層級切換**（只有一個層級時不顯示按鈕），預設為「目前所屬球隊的層級」，該層級沒有數據時退回大聯盟、再退回第一個有數據的層級。層級標籤一律來自數據本身，不再來自所屬球隊。
4. 逐場紀錄各層級混合、依日期排序，非大聯盟的場次標示層級。
5. 我的最愛戰報取「日期最新」的一場，不取陣列最後一筆。

### B. 小聯盟瀏覽

1. 支援層級：AAA、AA、A+、A（`src/constants/levels.ts`）。新人聯盟（ROK）只在球員數據中出現時顯示，不提供比分與戰績瀏覽。
2. **按需載入**：首頁比分板與戰績表加層級切換，只查詢被選中的層級；自動輪詢規則不變（只輪詢正在看的層級、只在有比賽進行時）。
3. **不新增小聯盟靜態球隊資料**。隊名直接用 API 回傳；主題色只給大聯盟 30 隊；小聯盟球隊頁以母隊代表色顯示並連回母隊。
4. 逐場比賽頁（boxscore）不需修改即可顯示小聯盟比賽。

## Alternatives Considered

1. **每個層級各發一次請求取球員數據**
   - *否決理由*：最多 5–6 次請求，且要先知道球員打過哪些層級。`leagueListId=mlb_milb` 一次就拿到。
2. **把 120 支小聯盟球隊烤進 `teams.json`**
   - *否決理由*：API 沒有隊色，要人工維護；所有只看大聯盟的使用者都得下載。改用 API 即時查詢（`max-age=60`，CDN 快取）。
3. **首頁一次顯示所有層級**
   - *否決理由*：實測流量變 5 倍，違反本專案「行動裝置省流量」的取向。

## Consequences

- 純大聯盟球員的球員頁請求增加約 0.8 KB（gzip）。
- 首頁只看大聯盟時，請求數與流量不變。
- 小聯盟球隊沒有自己的主題色。
