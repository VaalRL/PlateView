# 0004. 季後賽淘汰賽樹狀圖：由系列賽資料推導晉級關係，歷史範圍自 2012 年起

- Status: Accepted
- Date: 2026-09-24

## Context

首頁比分卡已經會顯示季後賽比賽（`/schedule` 預設包含 `gameType=F/D/L/W`），但沒有任何地方能看到「整個季後賽打到哪裡」。需求是淘汰賽樹狀圖，並能回看歷史年份。

實測 `GET /api/v1/schedule/postseason/series?season={y}&sportId=1`：

- 1903–2026 年皆有資料（1904、1994 為空），每年一次請求即可取得全部系列賽與每一場比賽。
- 系列賽 id 為「輪次字母_編號」：`F`＝外卡、`D`＝分區、`L`＝聯盟冠軍、`W`＝世界大賽。
- 以 `fields=` 精簡後約 20 KB 原始、1.2 KB gzip。
- 尚未開打的季後賽（2026 年 9/28 開打）已列出全部 11 組系列賽，未定席位以「佔位隊伍」表示（如 `AL Wild Card #3`、`AL 4/5 Winner`），各有獨立 team id。

## Decision

新增 `#/postseason/:season?` 頁面，歷史範圍 **2012 年起**（外卡制度確立、種子可由戰績推準的年份）。所有推導寫成 `src/utils/postseason.ts` 純函式，以真實 API 精簡回應作為測試 fixture。

### API 不直接提供、需由前端推導的部分

1. **晉級關係（樹的形狀）**：API 不說哪個外卡系列賽通往哪個分區系列賽，而且每年不同（2012 美聯外卡勝隊進 D_2、2019 進 D_1；2020 年每個分區系列賽有兩個來源）。
   - 以**隊伍比對**：外卡系列賽的勝隊出現在哪個分區系列賽，就接到那裡。
   - 尚未分出勝負時，接到同聯盟中「仍有佔位席位」且來源最少的分區系列賽（同數時取 id 較大者），外卡依 id 升冪逐一分配。注意尚未確定的輪空種子本身也是佔位（2026 年 D_2 為 `AL 3/6 Winner` vs `AL #2 Seed`），所以不能只看「有沒有空位」。這符合 2022 年起的慣例（D_1←F_2、D_2←F_1），但**只影響尚未開打時的排版**，比賽一有結果就改由隊伍比對決定。
   - 分區→聯盟冠軍→世界大賽依聯盟接（聯盟取自 `description` 開頭的 `AL`／`NL`）。
2. **種子**：API 沒有種子欄位。由 `/standings` 的 `clinchIndicator` 推算：`z`/`y`（分區冠軍）→ `x`（2020 年分區第二）→ `w`（外卡），同組內依 `leagueRank` 排序。以 2020、2025 兩年驗證與官方種子一致。
   - **只在首輪席位全部確定時顯示種子**。例行賽尚未結束時只有部分隊伍有 `clinchIndicator`，推出來的數字會是錯的。
3. **佔位隊伍**：以「是否為 `teams.json` 的 30 隊之一」判定，不用隊名正規表示式（佔位名稱格式不穩定：2022 為 `3 vs.6`、2025 為 `'A'`）。佔位隊伍顯示為「待定」並附原始佔位名稱，不查隊徽、不連結球隊頁。
4. **系列賽戰績**：自行累計 `status=Final` 且 `isWinner` 的場次。延賽（`Postponed`）的場次會與補賽重複列出，不能用場數計算。

### 外觀（2026-09-24 修訂）

依使用者提供的 MLB「Postseason Picture」海報重新設計：

- **每支球隊一格菱形**（不是每個系列賽一張卡），隊色底＋淺色帽徽（`team-logos/team-cap-on-dark/{id}.svg`），左上角圓標為種子序；尚未確定的席位為灰色菱形。
- **輪空種子直接放在分區賽欄**，每一格對齊送它進來的系列賽的中點；粗灰色直角連接線；美聯在左、國聯鏡像在右，世界大賽與冠軍在中央；欄頂是輪次名稱，欄底是賽制（3 戰 2 勝制等）。
- 因為各子樹高度不同，flex／grid 無法可靠對齊，改以純函式 `src/utils/bracketLayout.ts` 計算座標，整張圖以單一 SVG 繪製，依寬度等比縮放。
- 系列賽比數放在連接線交會點的小標籤上，點選後在圖下方顯示該系列賽明細與 G1–G7 連結；預設選取最近一場比賽所屬的系列賽。
- **不複製**海報上的 MLB 字標、世界大賽標誌與贊助商標誌。

### 快取

- 當季：staleTime 5 分鐘，不輪詢（逐場即時比分由首頁比分卡負責）。
- 往年：staleTime 24 小時，資料已不會變動。

### 明確不做的事（範圍邊界）

1. **不支援 2012 年以前**。資料其實拿得到，但 1969–2011 需要另一套樹形（無外卡輪），種子也推不準；等有需求再擴充，現有推導邏輯（依資料中有哪些輪次決定欄數）不需重寫。
2. **不做季後賽專屬的球員或排行榜數據**。那是另一項需求（`/stats/leaders` 會忽略 `gameType=P`，需改用 `/stats`）。
3. **不即時輪詢樹狀圖**。

## Alternatives Considered

1. **依年份寫死每一年的樹形**
   - *否決理由*：每年晉級對應都可能變（2012 vs 2019 已不同），寫死等於每年手動維護，且無法處理尚未開打的當季。
2. **以隊名正規表示式判定佔位隊伍**
   - *否決理由*：佔位名稱格式已變過一次，`teams.json` 本來就是 30 隊的單一來源，判斷更穩定。
3. **加 `hydrate=team` 取得聯盟歸屬**
   - *否決理由*：回應從 91 KB 漲到 166 KB；`description` 開頭已足夠判斷聯盟。

## Consequences

- 新增一個 lazy route，不影響首頁 bundle。
- 若 MLB 未來再改季後賽賽制，隊伍比對仍然成立；只有「尚未開打時的預設排版」可能需要調整。
